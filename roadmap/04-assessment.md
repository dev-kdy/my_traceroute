# 학습 평가 기준 — 일정보다 증거를 우선한다

## 1. 차시마다 4문항, 답변 전 정답 비공개

- **Rust 1문항(25점):** 개념을 정의하는 데 그치지 않고 실제 코드의 타입/제어 흐름을 예측.
- **네트워크 2문항(각 25점):** 표준상의 패킷 동작과 관측 결과가 의미하는 범위 설명.
- **C/Rust 해석 1문항(25점):** 원본의 함수 전체 제어 흐름을 읽고 Rust로 옮기면서 보존/개선할 점 구분.
- 한 번에 모든 정답을 제시하지 않는다. 답안 → 채점 → 오개념 보충 → **새로운 변형 문제** 재평가.
- 권장 합격 기준: **80점 이상 + 치명적 오개념 없음**, 단 점수만으로 주차 통과 불가. 최초 점수는 지우지 않는다.

## 2. 주차 완료의 다섯 가지 증거

| 영역 | 충족 예시 | 미충족 예시 |
|---|---|---|
| 개념 | 자신의 말로 Rust/네트워크 개념·Java와 차이를 설명 | 강사의 정의를 그대로 따라 말함 |
| C 독해 | 함수의 전체 호출/분기·상태 변화/실패 경로 설명 | TTL 한 줄만 기억하고 나머지를 모름 |
| 직접 구현 | 스스로 설계한 Rust 코드, 커밋, 이유와 변경 내역 | 답안 복사·출력만 흉내 |
| 검증 | 실제 명령·입력·stdout/stderr·exit code·정상/경계 사례 | 명령이 적혀 있으나 실행 결과 없음 |
| 패킷 의미 | 실제/통제된 대체 캡처·필드·Probe 매칭 근거 | ICMP 응답 출발지만 보고 목적지 성공 판단 |

해당 주차에서 실소켓을 다루지 않으면 패킷 필드 모의 데이터와 테스트 벡터를 사용한다. 모든 항목은 `미진행`/`진행 중`/`보충 필요`/`실제 증거로 통과` 가운데 하나로 기록한다.

## 4. 네 마일스톤

### M1 — W03 / 네트워크 없는 실행형 CLI

- 목적지/옵션을 `Config`로 나타내고 입력 오류를 `Result`로 반환.
- `-f`/`-m`/`-p`/`-q`/`-I`의 사용성·경계값 테스트.
- **대체 불가 증거:** 다른 입력에서 예상한 도움말/오류·종료 코드, 자동 테스트.
- 소켓을 썼거나 실제 경로가 보일 필요 **없음**.

### M2 — W06 / 송신과 ICMP 수신 분리

- TTL이 다른 UDP 패킷이 실제 인터페이스에서 관측됨.
- ICMP Time Exceeded와 Port Unreachable Type/Code를 수신/기록하거나 통제된 패킷으로 검증.
- `socket2`/Raw Socket/`CAP_NET_RAW` 권한의 이유와 실패를 설명.
- 응답 매칭을 완성하지 않았다면 **완성했다고 쓰지 않는다**.

### M3 — W10 / 의미적으로 올바른 2모드 traceroute

- UDP: 인용된 원래 패킷을 확인한 **ICMP Type 3 Code 3** 종료.
- ICMP Echo: 요청 ID/Sequence와 연관된 **Echo Reply Type 0 Code 0** 종료.
- 중간 TTL=1부터 연속 홉 전송, 여러 Probe, timeout/RTT, 외부 ICMP 무시.
- 테스트 및 캡처로 송신·수신/실패·목적지 판정을 재현.

### M4 — W12 / 독립 개발자 최종 실기

- 빈 crate 또는 깨끗한 체크아웃에서 개발 도구를 구성하고 독립적으로 빌드.
- 예상하지 못한 유효/무효 입력과 ICMP 응답을 제시해도 스스로 진단·수정.
- 격리 환경의 2개 이상 라우팅 홉(가능하면 Linux namespace)에서 응답 해석/실험 한계를 설명.
- 사용법, 권한, 테스트, 경계값, 알고리즘 한계, C 원본과 설계 차이 문서화.
