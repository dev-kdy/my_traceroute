# W11 — 오류·경계·회귀 테스트와 C 원본 보안성 재검토

**선수조건:** W10 M3 두 모드. 동작하는 코드를 **환경 변화·비정상 패킷에도 안전하게** 만드는 주차다. 외부망 없이 가능한 단위 테스트와 권한이 필요한 통합 실험을 명확히 분리한다.

**결과물:** 재현 가능한 회귀 테스트 모음, C 구현의 위험 가정 분석표, 종료조건·오류처리 보강, CI 가능한 품질 명령 로그.

## 1차시 — 원본 C 코드의 경계·오류 경로 감리

### 반드시 확인할 실제 원본

- [`check_packet.c`](https://github.com/Dauie/traceroute/blob/master/src/check_packet.c): 고정 `IPV4_HDRLEN` 오프셋과 포인터 캐스팅. 실제 길이/IHL 확인이 코드에 있는지 확인.
- [`send_recv_echo.c`](https://github.com/Dauie/traceroute/blob/master/src/send_recv_echo.c): `select` 실패·0 반환 시 `*` 출력/`FAILURE`; 호출자가 반환값을 무시했을 때 위험한 stale/zero-filled buffer 경로.
- [`set_addr_iface.c`](https://github.com/Dauie/traceroute/blob/master/src/set_addr_iface.c): `setsockopt` 성공=0/실패=-1인데 `if (!(setsockopt(...)))` 조건 사용; `parse_args` vs `create_sock` 순서.
- [`traceroute.c`](https://github.com/Dauie/traceroute/blob/master/src/traceroute.c): 마지막 buffer의 출발지 IP 비교 종료, TTL과 헤더 갱신 시점.

**중요:** 검토 가설과 **재현으로 확인된 결함**을 명확히 구별. 직접 C 컴파일이 어려운 경우 외부 의존성 심볼릭 링크(`libft`/`ping`)를 기록하고 Rust 재현 단위 테스트에서 같은 위험 조건을 만들어 검증하되 'C 실험 재현 완료'라고 쓰지 않는다.

### Rust 개념

- Unit test/Integration test의 역할; `#[test]`, `assert_eq!`, `assert!`, 테스트 fixture/모의 객체.
- `Result` 기반 오류 분류: 잘린/무관/유효하지만 예상 밖 ICMP/OS error/timeout.
- 불변 데이터와 순수 파서로 소켓 권한 없이 빠르게 테스트하는 구조.
- `cargo fmt --check`(스타일), `cargo clippy -- -D warnings`(정적 진단), `cargo test`(행동 검사) 역할은 서로 다르다.
- Java JUnit·Testcontainers와 비유하되 테스트 목적과 Rust 테스트 harness 차이 설명.

### 직접 테스트 설계 순서

1. **Risk Register** 작성: 입력 값, 위험 조건, 예상 failure mode, Rust 보호 장치, 재현 방법.
2. W04 파서의 길이 0/1/19/20/IHL 6/Total Length 부족·과다 사례를 테스트.
3. UDP/ICMP quoted 영역 부족·Endian 변조·잘못된 Protocol/Type/Code 테스트.
4. W07의 다른 Probe·늦은·중복 응답·무관 IP/Port 테스트.
5. W08의 Timeout/Deadline·clock 경계/시계 불변성 테스트.
6. W09~10의 올바르지 않은 종료 신호를 랜덤 순서로 주입한 테스트.
7. 각 발견된 실패에 '처음 상태 → 재현 → 수정 → 회귀 테스트' 기록.

## 2차시 — 테스트 인프라와 문서의 신뢰성

### 개념

- Unit(순수 함수) vs Integration(프로세스/소켓) vs End-to-End(실제 경로). 실패 층위를 섞지 않는다.
- **CI는 외부 네트워크/관리자 권한 없이** `cargo test`와 `fmt`/`clippy`를 실행할 수 있어야 한다.
- 통제된 VM 실소켓 테스트는 명시적인 옵션/별도 실행 절차로 분리.
- 테스트 커버리지 숫자보다 **잘못된 결과를 막는 반례**가 중요.
- 공용 수신 buffer와 함수 경계를 바꿀 때 side effect를 격리, 로그 출력과 protocol parsing을 분리.

### C ↔ Rust 설계 비교 과제

| C에서 관찰한 형태 | Rust에서 선택할 안전 조건 |
|---|---|
| 임의 오프셋 포인터 캐스트 | 실제 길이·IHL 기반 slice |
| 오류 반환 무시 | 결과 타입으로 오류/Timeout 명시 |
| 마지막 버퍼 IP로 종료 | 관련 Probe + 종료 Type/Code 검증 |
| 한글자/정수 오류 출력 | 내부 오류 분류와 사용자 메시지 분리 |
| 전역 또는 구조체의 많은 가변 상태 | 최소한의 가변 실행 상태와 불변 설정 |

**코드를 대신 써주지 않는다:** 테스트의 입력/예상은 제공하지만 구현 함수는 학습자가 직접 작성. 미처리 오류가 있으면 정상 사례보다 우선 보강.

### 권장 테스트 매트릭스

- **길이:** 0~19바이트, 20바이트, IPv4 옵션, 잘린 quoted inner IP, 잘린 UDP/Echo 헤더.
- **값:** 잘못된 Version/IHL/Total Length/Checksum/UDP Length, 미지원 Protocol, ICMP Code.
- **상관관계:** 다른 Probe의 ID·Sequence·Port, 겹치는 응답, 지연·중복·순서 변경.
- **시간:** deadline 직전/직후, 무관 응답 후 남은 시간, 소켓 반환 오류.
- **종료:** Time Exceeded로 오종료 없음, 부적합 Port Unreachable 무시, 잘못된 Echo Reply 무시.
- **운영:** 관리자 권한 없는 CI 성공, 실소켓 통합 테스트는 기본 실행에서 제외.

## Exit Gate

- [ ] 심각한 패킷 파싱 입력으로 panic 없이 오류/무시.
- [ ] 매칭·종료·deadline의 반례 테스트를 충분히 보유.
- [ ] `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test` 실제 종료 코드 0 제출.
- [ ] 외부망/Raw Socket 권한 없이 단위 테스트 실행.
- [ ] 원본의 4가지 위험 가설을 원본 코드와 분리 설명하며 재현 여부 기록.
- [ ] 코드/문서/테스트 커밋과 차시당 4문항 답변.
- [ ] W12 전 '현재 한계' 목록: OS 차이·필터·NAT·ECMP·비대칭·권한.

**주의:** 기능이 실제로 정상 작동하더라도 반례 테스트가 없으면 W11 미통과로 남긴다.

**저장/진도:** 학생의 코드·답·로그가 확인된 경우 `roadmap/state.json` 및 `roadmap/journal/W11.md`에 기록할 변경안을 제시하고 승인을 받은 뒤 반영. 오답 최초 기록/미검증을 지우지 않는다. `src/`와 Git 원격을 무단으로 변경하지 않는다.
