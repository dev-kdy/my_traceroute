# W09 — UDP traceroute MVP와 정확한 종료 조건

**선수조건:** W05 UDP 송신, W06 ICMP 수신, W07 Probe 매칭, W08 RTT·deadline. 이제까지 만든 **기능을 합쳐 처음으로 의미 있는 UDP traceroute**를 완성한다.

**목표:** TTL을 1에서 올리고 홉마다 Probe를 보내며 응답/무응답을 표시하되, **내 Probe와 일치하는 올바른 ICMP Port Unreachable**만 정상 도달로 인정한다.

## 1차시 — TTL·Probe 엔진과 상태 전이

### 개념

- 루프의 외부 상태: 현재 TTL, 최소/최대 TTL, 현재 Probe, 목적지 도달 여부, 중단/오류.
- 내부 Probe 상태: 송신 준비 → 송신 → 수신 대기 → 응답 매칭 → 결과/Timeout.
- **동시성보다 정확성 우선:** 처음에는 순차 Probe 처리. 성능 최적화는 별도 근거와 테스트 후 검토.
- Rust `for`/`while`/`loop`와 `break`, 불변 설정 vs 가변 실행 상태.
- 재사용 가능한 함수 책임: `prepare_probe`/`send_probe`/`receive_icmp`/`classify_response`/`format_hop`(이름은 예시일 뿐 강제하지 않음).
- Java의 service loop/state machine에 비유하되 Rust의 `enum`은 가능한 상태를 타입으로 제한한다.

### C 원본 전체 독해

[`traceroute.c`](https://github.com/Dauie/traceroute/blob/master/src/traceroute.c)의 `ping_loop` 전체를 **함수 단위**로 읽는다. `run && ttl<=max_ttl` → probe 0 → fill/send/clear/recv/handle → TTL 증가 → update_echopkt → 마지막 IP로 종료. 기능 대응표에 **Rust에서 바꿀 점**을 반드시 써야 한다: 수신 결과를 무시하지 않기, 매 Probe 명확한 식별자, 종료 판정 순서, 패킷 헤더 갱신 시점.

### 직접 설계·구현 과제

1. 알고리즘을 자연어 상태도로 먼저 작성. **왜 TTL 증가가 홉의 Probe 전송 후인가?**
2. 순수한 `step`/상태 전이 함수(또는 그에 준하는 설계)를 구성해 socket과 분리.
3. 첫 TTL과 max TTL의 경계(1과 1, 1과 30, 시작>최대)를 시험.
4. 홉당 Probe 3개와 무응답 `*`를 표시하되 3개를 한 응답으로 합치지 않는다.
5. 수신 socket이 실패하면 오류 보고, Timeout이면 `*`; 유효 응답은 IP/RTT/Type 표시.
6. 사용자 강제 종료·네트워크 오류를 **정상 목적지 도달**과 분리.

### 검사표

| 사건 | 기대 엔진 동작 |
|---|---|
| 중간 라우터 11/0 + 내 Probe 일치 | 홉 기록, 다음 TTL 계속 |
| Timeout | 해당 Probe `*`, 다른 Probe 진행 |
| 관련 없는 ICMP | 기록/무시, 현재 Probe 성공으로 처리 금지 |
| 마지막 허용 TTL 도달 | 더 큰 TTL로 송신하지 않고 최대홉 종료 |
| 대상 IP의 ICMP이지만 종류/quoted fields가 부적합 | 도달 처리 금지 |

## 2차시 — UDP 목적지 판정

### 프로토콜 개념

- IPv4 UDP traceroute는 일반적으로 UDP 도착 목적지의 **수신 포트가 닫혀** ICMP Destination Unreachable/Port Unreachable **Type 3 Code 3**이 돌아오는 특성을 이용.
- 단, **ICMP 출발지 주소 일치만으로** 도달을 판단하지 않는다. Type/Code와 **인용된 원래 UDP Probe의 주소/포트/식별자** 검증 필수.
- ICMP 11/0은 중간 홉을 의미하고 UDP Port Unreachable과 의미가 다르다.
- UDP 목적지에 실제 리스너가 있거나 방화벽이 ICMP를 막으면 도달 신호를 관찰하지 못할 수 있다.

### C 원본 재검토

[`ping_loop`](https://github.com/Dauie/traceroute/blob/master/src/traceroute.c)는 마지막 `resp_buff`의 `ip_src`와 `mgr->to.sin_addr`를 비교하는 것으로 `flags.run`을 내린다. **이 검사에 어떤 조건이 빠져 있는지** Rust 설계로 설명. '원본은 틀렸다'는 결론이 아니라 **검증되지 않은 전제**와 그 실패 사례를 제시한다.

### 직접 구현 단계

1. 도달 판단 함수의 입력을 **Probe + 구문 분석된 ICMP + quoted original packet**으로 설계.
2. `ICMP 11/0`은 중간홉, `3/3`은 검증된 경우 도달, 다른 Type/Code는 기타로 분기.
3. 오래된 Probe/잘못된 포트/맞지 않는 대상의 ICMP 3/3으로 종료하지 않는 테스트.
4. 도달 확인 시에만 추가 TTL 송신을 중단하는 상태 전이 테스트.
5. 실측 캡처의 각 응답을 Probe 식별 정보와 함께 매칭해 기록.
6. 기존 W07~08 단위 테스트가 깨지지 않는지 회귀 검사.
