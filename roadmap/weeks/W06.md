# W06 — Raw Socket·ICMP 수신·권한 (마일스톤 M2)

**선수조건:** W05에서 UDP 송신 캡처 확인, W04에서 안전한 바이트 파싱 완료. Linux/Ubuntu VM의 최소 권한과 macOS API 차이 이해. **일반 UDP 송신 + 별도 ICMP 수신**을 기본 아키텍처 후보로 검토한다.

## 1차시 — Raw Socket이 필요한 이유

### 개념

- 일반 UDP 소켓과 Raw Socket: 애플리케이션이 전송 헤더를 얼마나 직접 다루는가, 수신 ICMP 오류를 어떤 API로 얻는가.
- IPv4/ICMP Protocol=1, UDP Protocol=17. `IP_HDRINCL`은 소켓 옵션과 OS에 따라 지원·영향이 다르다.
- `socket2`: OS 수준 소켓 생성/설정을 추상화한 Rust crate. 우선 공식 문서와 사용 중인 버전을 확인.
- Linux `CAP_NET_RAW`, root, capabilities, 권한 부족 시 `PermissionDenied` 처리. **무조건 root로 전체 프로그램 실행하지 않기**.
- Java `DatagramSocket`/`SocketChannel`과 OS 소켓의 관계. Rust는 관리자 권한 여부를 컴파일 타임에 보장하지 못한다.
- 수신 버퍼는 보이는 모든 ICMP를 **내 Probe 응답이라고 판단하면 안 된다**. W07에서 매칭.

### C 원본 전체 분석

[`main.c`](https://github.com/Dauie/traceroute/blob/master/src/main.c) `create_sock`: 송신 raw socket(UDP/ICMP)·수신 raw ICMP socket 분리, `ft_setsock_hdrincl` 호출, UDP 모드 bind. [`send_recv_echo.c`](https://github.com/Dauie/traceroute/blob/master/src/send_recv_echo.c)의 `recv_echo`: `select` 대기 후 `recvfrom`, 시간 초과면 `*` 출력/실패 반환. **반환값을 호출자가 활용하는지** `ping_loop`까지 따라간다.

### 직접 설계 및 실습

1. 송신(일반 UDP)과 수신(ICMP) 인터페이스를 분리하는 함수·타입 계약 설계.
2. 수신 socket 생성 실패 시 **명확한 OS 오류**를 사용자에게 전달.
3. 수신 버퍼 크기와 실제 읽은 `nbytes`를 함께 보존하도록 설계. 버퍼 전체 용량을 받은 데이터 길이로 오인하지 않는다.
4. 수신 결과의 `timeout/packet/error`를 어떻게 구분할지 값 타입 설계.
5. Ubuntu VM에서 최소권한 테스트(권한 없이 실패하고, 승인된 안전 조건에서 필요한 권한으로 성공). macOS는 시스템별 제약을 설명하고 VM 실습으로 대체 가능.
6. 오류 시 소켓 리소스 정리가 어떻게 일어나는지 `Drop`과 연결.

## 2차시 — ICMP Type/Code와 수신 데이터

### 표준 원리

[`RFC 792`](https://www.rfc-editor.org/rfc/rfc792): 중간 라우터의 ICMP Time Exceeded **Type 11, Code 0**, UDP 목적지의 Port Unreachable **Type 3, Code 3**, ICMP Echo Reply **Type 0, Code 0**. **수신했다고 무조건 종료하지 않는다.** ICMP 오류에는 원래 IP 헤더와 최소 전송계층 부분의 인용(quoted) 정보가 있다.

### C 원본 분석

`recv_echo`의 `select` 대기 시간, `FD_SET`와 timeout/성공/오류 분기, `recvfrom`으로 실제 데이터가 들어오는 순간을 설명. [`handle_response.c`](https://github.com/Dauie/traceroute/blob/master/src/handle_response.c)의 `print_specials`에서 ICMP 종류에 따라 표시가 바뀌는 전체 분기를 따라간다.

### 구현 단계

1. 캡처에서 가져온 ICMP 바이트를 W04의 파서로 해석하는 **수신 함수 계약** 작성.
2. Outer IPv4 헤더 길이 + ICMP 기본 헤더 길이 검사.
3. Type/Code 분류와 로그를 구현하되 아직 목적지 도달 판단은 **보류**.
4. ICMP Time Exceeded/Port Unreachable/알 수 없는 ICMP/잘린 buffer 테스트.
5. 읽은 길이가 부족하거나 소켓 오류면 panic 대신 명시적 결과를 반환.
6. 실제 수신 성공/수신 실패/timeout을 **로그와 pcap으로 구분**.

### 필수 테스트

| 상황 | 기대 |
|---|---|
| 수신 성공, ICMP 11/0 | 중간 홉 오류로 분류(도달 아님) |
| 수신 성공, ICMP 3/3 | Port Unreachable로 분류(내 Probe인지는 아직 미검증) |
| 알 수 없는 Type/Code | 잘못된 종료 없이 기타/무시 |
| 부족한 버퍼/IHL 오프셋 변경 | 안전한 오류/무시 |
| 수신 기한 도달 | timeout 상태, stale 응답 사용 금지 |
| raw socket 권한 없음 | 이해 가능한 OS 오류, 테스트 환경 지침 |

**마일스톤 M2는 송수신 경로까지다.** 무관한 응답 걸러내기(정확한 Probe 매칭)는 W07, deadline/RTT는 W08, 종료 판정은 W09~10. 단계를 임의로 앞당겨 '완성' 처리 금지.
