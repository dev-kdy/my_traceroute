# W03 — Result·Option·CLI·DNS와 입력 검증

**선수조건:** W02의 소유권·`Config`·`ProbeProtocol`. 이번 주는 실제 소켓을 열지 않는다. **M1: 네트워크 없이 실행할 수 있는 안전한 CLI** 완성이 목표다.

## 1차시 — Rust의 오류와 선택적 값

### 개념

- `Option<T>`: 값의 부재를 정상적인 상태로 표현. Java `null`과 달리 호출자가 분기하도록 타입화.
- `Result<T,E>`: 성공/실패의 명시적인 반환. Java 예외와 다르게 일반적인 값이며 `?`는 실패 시 호출자에게 반환.
- `match`/`if let`: 모든 경우/필요한 경우 분기. `unwrap`으로 사용자 오류를 숨기지 않는다.
- `mod`/`use`: 파일을 작은 책임별로 분리. Binary crate/Library crate의 차이는 Cargo와 연결.
- 파싱과 검증을 분리: 문자열 → 숫자·IP 타입 → 범위·조합 검사 → 유효한 설정.

**Java 비교 과제:** `Integer.parseInt` 예외를 처리하는 Java CLI와 Rust `parse::<u16>()`/`Result` 방식에서 오류가 함수 시그니처에 드러나는 차이를 설명. Exception이 Rust `Result`와 완전히 동등하다고 쓰지 않는다.

### 원본 독해

[`main.c`](https://github.com/Dauie/traceroute/blob/master/src/main.c) 전체 `set_args`/`parse_args`: 인자 순회, `-I` 플래그, 옵션별 함수 포인터 호출, 목적지 해석 실패·인자 누락 처리를 지도화한다. 성공 반환을 보고 모든 경계값을 체크했다고 단정하지 않는다. 원본 `main()`의 파싱 이후에 `create_sock()`를 호출한다는 점과 상태 초기화 순서를 표시.

### 단계별 직접 실습

1. 사용자 입력 문자열 `"1"`, `"255"`, `"0"`, `"256"`의 TTL 변환 가능성/유효성을 **타입과 정책으로 나눠 예측**.
2. 문자열→정수 변환 결과를 `match`로 분기하고 오류 메시지를 작성.
3. 반환 타입을 `Result`로 하여 잘못된 입력을 호출자에 전달.
4. 옵션이 없을 때 기본값 적용과 필수 인자 누락을 구분.
5. 오직 로컬 출력과 테스트만 실행. 네트워크 IO는 아직 추가하지 않는다.

**예상 테스트:** 빈 입력, 숫자가 아닌 텍스트, 정수 범위를 넘는 입력, 정상 숫자. `cargo test` 출력/종료 코드 제출.

## 2차시 — C 옵션 처리·DNS·Rust CLI

### 개념

- `std::env::args` 또는 `clap`를 이용한 인자 처리. 학습은 std 인자 구조를 이해한 뒤 `clap`을 도입할지 결정한다.
- `IpAddr`/`Ipv4Addr`/`ToSocketAddrs`: DNS 이름과 IPv4 주소를 구분. **이 프로젝트 기본 구현은 IPv4**; IPv6 주소가 나오면 어떻게 처리할지 명시.
- `-f` 첫 TTL, `-m` 최대 TTL, `-q` 홉당 Probe, `-p` UDP 기본 포트, `-I` ICMP Echo 모드. macOS 시스템 traceroute와 본인 CLI 옵션 구문은 다를 수 있음.
- 입력 실패 vs DNS 실패 vs 네트워크 실패의 경계(실제 송신은 나중에).

### C 원본 전체 읽기

[`set_port_ttl_probe.c`](https://github.com/Dauie/traceroute/blob/master/src/set_port_ttl_probe.c)의 `set_init_ttl`, `set_max_ttl`, `set_port`, `set_probe_amt`: 어떤 범위만 확인하고 어떤 상한은 놓치는지 실제 조건식을 읽는다. `DEF_MAX_TTL=30`/`DEF_PROB_AMT=3`/`MAX_PROB_AMT=10`은 참고할 **원본 설정**이지 무조건 재현할 표준은 아니다. [`traceroute.h`](https://github.com/Dauie/traceroute/blob/master/incl/traceroute.h)와 대조.

### 과제: 사용 가능한 CLI를 직접 설계

1. `my_traceroute --help`에서 보여줄 옵션, 기본값, 오류를 표로 작성.
2. 인자→`Config` 변환 흐름 및 함수 반환 타입을 설계.
3. `-m < -f`/Probe 0/포트 범위 초과/옵션 누락을 오류로 처리할 정책 설정.
4. 허용할 IPv4 주소와 도메인 입력을 구분. DNS 조회를 선택했다면 외부 네트워크 없는 단위 테스트와 분리.
5. 사용자 오류에서 panic 대신 메시지+비정상 종료코드 반환.
6. C 원본의 옵션 함수와 Rust 모듈 책임을 대응 설명.

### 필수 경계/음성 테스트

| 입력 | 기대 분류(답안 코드는 직접 설계) |
|---|---|
| 정상 도메인/IPv4와 옵션 기본값 | 유효 설정(실송신은 아직 X) |
| 목적지 누락 | 명확한 인자 오류 |
| `-f 0` / `-m 256` | TTL 범위 오류 |
| `-f 8 -m 4` | 시작 > 최대 TTL |
| `-p 0` / `-p 65536` | UDP 포트 범위 오류 |
| `-q 0` / 설정 상한 초과 | Probe 수 오류 |
| 알 수 없는 옵션, 숫자 자리에 텍스트 | 파싱 오류 |
| DNS 실패/IPv6만 해석되는 대상 | 본 프로젝트 IPv4 정책에 따른 설명 가능 오류 |
