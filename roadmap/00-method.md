# 학습 방법 — 독립적으로 traceroute를 완성하기 위한 교수 계약

## Antigravity CLI 운영

이 문서의 학습 원칙은 루트 [AGENTS.md](../AGENTS.md)와 [CLI 실행](07-antigravity-cli.md), [단계별 세션 계약](08-session-protocol.md)을 통해 **실제 터미널 에이전트 행동**으로 적용한다. 현재 주차와 다음 과제는 [state.json](state.json), 24차시 목표는 [curriculum.json](curriculum.json)에서 확인한다. AI가 자동으로 코드 수정·진도 이동·명령 실행을 하지 않도록, **학습자 제출 → 튜터 검토 → 검증 → 저장 승인** 순서를 지킨다.

## 학습의 성공 정의

최종 결과는 단순히 `traceroute`와 비슷한 문장을 출력하는 CLI가 아니다. 학습자는 **(1) 패킷·프로토콜을 설명 (2) Rust 타입·소유권으로 안전하게 구현 (3) 실제 ICMP를 해당 Probe와 연결 (4) 실패와 관측 한계를 이해 (5) 새로운 조건에서 스스로 수정**할 수 있어야 한다.

루트 [README](../README.md)의 12주·24차시 목표를 유지한다. 문서에 적힌 날짜만으로 완료하지 않고, 증거를 제출한 뒤 다음 차시로 이동한다. 차시 순서는 필요하면 조정하되 **Ownership(2주)·패킷 바이트(4주)·소켓(5~6주)·매칭(7주)·종료(9주)** 선후관계는 지킨다.

## 한 차시의 진행 절차

| 단계 | 학습자 행동 | 튜터 행동 | 통과 증거 |
|---|---|---|---|
| 0. 회상(5분) | 지난 개념을 암기하지 않고 직접 설명 | 1문제만 질문 | 자신의 말 2~3문장 |
| 1. 개념(15분) | Rust 1~2개·네트워크 1개가 왜 필요한지 말함 | Java와 **비슷한 점/다른 점** 설명 | 예상 동작 설명 |
| 2. C 독해(15분) | 함수의 **전체** 호출·분기·반환·상태 변화 지도 작성 | 확인한 원본과 추정 분리 | 순서도·표 |
| 3. 실습(30분) | 10~30줄 내외 단위 기능을 직접 작성 | 정답 대신 작은 테스트·힌트 | 코드·수정 내역 |
| 4. 검증(15분) | 성공·실패·경계 입력, 예상·실측 대조 | 테스트/pcap의 필드 같이 해석 | 명령+종료코드+실측 |
| 5. 평가(10분) | Rust 1·네트워크 2·C/Rust 코드 독해 1 답변 | 정답은 제출 후 공개, 오개념 보충 | 첫 답·오답·재평가 |

**한 대화 턴에는 하나의 작은 과제만 제시한다.** 로드맵에 여러 주차의 과제 범위가 쓰여 있어도 실제 수업은 차례로 진행한다.

## 힌트 사다리(정답 제공 정책)

- **H0 계약:** 입력·출력·제약·검증 조건만 알려준다. 학습자가 첫 코드를 작성한다.
- **H1 질문:** 바뀌는 변수는 무엇인지, 누가 TTL을 수정하는지 등 사고 방향만 제시.
- **H2 의사코드:** 언어 중립적인 흐름을 글이나 도표로 제시.
- **H3 작은 문법 단서:** 현재 막힌 구문만 1~3줄, 코드의 **각 줄에 한국어 주석**.
- **H4 제한된 함수:** 두 번 이상의 힌트로 해결되지 않거나 학습자가 명시적으로 요청하면 해당 부분만 코드 제공.
- **H5 전체 풀이:** 학습자가 스스로 구현·제출한 후 복기하거나 **정답을 명시적으로 요청한 경우에만**. 베껴 쓴 결과는 '독립 구현'으로 통과 처리하지 않는다.

오답이 생기면 정답을 바로 말하지 말고, **최소 반례와 추가 질문**으로 원인을 밝힌다. 단, 프로토콜·안전에 관련된 잘못된 사실은 즉시 정정한다.

## Java ↔ Rust 비교 시 절대 혼동하지 않을 것

| 비교 | 비슷한 부분 | 다른 부분 |
|---|---|---|
| `javac` / `rustc` | 코드를 컴파일 | Rust는 보통 네이티브 실행 파일을 생성, JVM 필수 아님 |
| Gradle·Maven / Cargo | 빌드·의존성 | Cargo는 일반적인 Rust 패키지·도구 워크플로의 중심 |
| SDKMAN / rustup | 개발 도구 설치·버전 | Rust target/toolchain 관리의 구체적 모델은 별도 학습 |
| Java `final` / Rust `let` | 변수 재할당 제한 | Rust 소유권·가변 빌림과 동일 개념이 아님 |
| Java String / Rust `String`·`&str` | 문자열 표현 | Rust `String`은 소유한 UTF-8 버퍼, `&str`은 문자열 슬라이스 |
| Java 예외 / Rust `Result` | 실패를 호출자에게 전달 | `Result`는 값 타입이고 `?`는 오류 경로 조기 반환 |
| Java 인터페이스 / Rust `trait` | 공유 동작 명세 | 구현·연관 타입·소유권·제네릭의 동작 차이가 있음 |
| Java GC / Rust RAII | 자원 수명 관리 | Rust는 흔히 컴파일 타임 소유권 검사, 일반 GC 없음 |

## C 원본 읽기: 전체를 보되 깊이를 조절

1. **전체 함수 시그니처**: 인자/반환/외부 상태를 찾아 적는다.
2. **제어 흐름 완독**: `if`·`while`·에러 분기까지 호출 순서 지도 작성.
3. **금주 핵심 세부 분석**: 이 단계의 Rust와 관련된 구문만 줄 단위로 설명.
4. **미래 기술 표시**: 네트워크 I/O/체크섬 구현 등 다음 주에 배울 내부는 '이름·역할·경계'를 먼저 알고 보류.
5. **행동 예측**: TTL과 응답 버퍼를 구체적인 값으로 추적해, 다음 송신 바이트가 무엇인지 설명.

예: `ping_loop`에서 `mgr->ttl++` → `update_echopkt` → 다음 `fill_packet` 순서가 중요하다. 송신 상태, 구조체, 실제 바이트 버퍼를 다른 상태로 그려야 한다.

## 복습과 자기 설명

- 학습 종료 직후: 새로운 용어 3개를 정의, 원본에서 함수 1개 실행 흐름을 재진술.
- D+1: 노트 없이 어제 코드 일부를 다시 쓰기.
- D+3: 오류 시나리오를 제시하고 값 변화 추적.
- D+7: 같은 기술을 Java 코드나 일상 비유와 비교하되, 비교의 한계도 말하기.
- 마일스톤: 처음 보는 입력/네트워크 조건을 받아 스스로 설계·테스트를 수정하기.

**성공 기록의 최소 형식:** 환경·명령·입력·예상·실제 stdout/stderr·exit code·pcap/테스트 결과·해석·불확실성. 실행하지 않았으면 `미검증`. 빨리 넘기는 것보다 정확한 설명을 우선한다.

## AI 활용의 범위

AI는 개념 설명/질문/코드 리뷰/테스트 벡터/프로토콜 근거 탐색을 돕는다. **학습자를 대신해 완성 소켓·파서·트레이스 엔진을 작성하는 도구로 사용하지 않는다.** 학습이 끝나면 'AI가 없었다면 설계·구현할 수 있는지'로 실제 실력을 재평가한다.
